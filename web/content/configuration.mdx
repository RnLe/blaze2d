# API & TOML

A `blaze2d/1` configuration describes a calculation independently of its runner.
Rust resolves defaults, validates geometry and numerical settings, and expands studies.
Python, the command line, and the Workbench consume the same normalized jobs.

## A band calculation

<ExampleSource slug="square-rods" language="toml" />

The optional sections are `[eigensolver]`, `[dielectric]`, `[results]`, and
`[[sweeps]]`. Choose `task = "bands"` with `[bands]`, or `task = "operators"`
with `[operators]`. Supplying both task sections is an error. Unknown keys and
unsupported precision, geometry, material, or dimension requests also fail explicitly.
An empty object list is a valid homogeneous medium.

| Section | Responsibility |
| --- | --- |
| `geometry` | Direct lattice, background permittivity, and named objects |
| `grid` | Scalar resolution or an explicit `[nx, ny]` |
| `bands` / `operators` | Calculation, band window, and sampling |
| `sweeps` | Ordered, typed parameter axes |
| `eigensolver` | Precision, stopping tolerance, iteration limit, and block size |
| `dielectric` | Sampling, smoothing, mesh size, and interface tolerance |
| `results` | Retention of optional large datasets |

Object names are unique. Use `geometry.objects.rod.radius` as a sweep target.
A lattice uses either a preset with lengths, or `type = "custom"` with explicit
vectors. Rectangular lattices require `b`; oblique lattices also require `angle_deg`.
The current release supports two-dimensional circles and positive scalar permittivity.

## Defaults and coordinates

Defaults are grid 32 × 32, `f64`, eight bands, and analytic dielectric smoothing
with mesh size 3 and interface tolerance `1e-6`. Eigenvector retention is off.
Band calculations use tolerance `1e-6` and 200 iterations. Operators use `1e-8`
and 300 iterations, starting at band 0 with four retained and eight upper remote bands.

The stopping tolerance measures **relative eigenvalue changes**. Fresh operator
residuals and orthogonality defects are reported separately. Set
`operators.fail_on_residual` to enforce a normalized residual acceptance threshold.
Without that gate, a completed calculation may still contain inaccurate remote eigenvectors.
Band results report fresh residuals and B-orthogonality without rotating the tracked fields.
Operator results include the existing final Rayleigh-Ritz refinement.

For an explicit band acceptance contract, add:

```toml
[bands.accuracy]
max_relative_residual = 1e-5
max_absolute_residual = 1e-7
max_orthogonality_defect = 1e-8
```

Every returned mode must pass the relative **or** absolute residual limit, the
whole block must pass B-orthogonality, and every requested point must meet the
stopping criterion. The absolute branch remains meaningful at zero or near-zero
Gamma modes. Limits must be finite and positive; omitted limits take the values
above. Omitting the entire section preserves the previous reporting-only behavior.
For explicit accuracy in either precision, tentative soft locks also require
fresh residual qualification before deflation. This prevents eigenvalue
stagnation from freezing inaccurate fields. The gate covers ordinary solves,
reuse, final fallbacks, metric support and external sampled inputs. It never
silently tightens the stopping tolerance.
Rejected ordinary jobs preserve their computed arrays in `partial_result` and
follow the runner's error policy. An empty or invalid certificate cannot pass.

This is a backward-error check on the selected finite pencil. Metric-support
acceptance uses its projected pencil; material/grid convergence, continuum
accuracy and complete low-band coverage remain separate questions.

`absolute_residuals` contains $\|Au-\lambda Bu\|/\|u\|$. Use it near Gamma,
where a small denominator can make normalized residuals misleading. Both arrays
follow the returned band order; their conventions and units are recorded in metadata.

- Lattice vectors and circle radii share one reference length.
- Object centers and registry displacements use direct fractional coordinates.
- Reciprocal fractional coordinates use $k = 2\pi A^{-T}q$.
- Cartesian wavevectors are angular wavevectors in inverse reference-length units.
- Frequencies are $\sqrt{\lambda}/(2\pi)$, in units of $c$ per reference length.
- Operator derivatives keep their recorded differentiation basis. Changing the carrier coordinate representation does not change that basis.

A band path is a preset, vertices with `intervals_per_segment`, or already sampled
points. These forms cannot be combined. A path with $S$ segments and $N$ intervals
per segment has $SN+1$ samples. Distances use the reciprocal Cartesian metric.
Labels retain their exact sample indices. The manual default recomputes a closing
Gamma point; certified identical-point reuse can eliminate that solve.

## Symmetry and execution reports

<ExampleSource slug="certified-symmetry" language="toml" />

The recommended native f64 path is explicit `policy = "auto"` with a suitably
tight stopping tolerance and an accuracy gate. `public-sweep-v3` considers PT
on equal square/triangular grids 31–65 with 8–16 bands and stopping tolerance
at most `1e-13`. The ordinary `1e-6` tolerance uses the complex path: measured PT
attempts failed certification and added work there. Repeated-point reuse still
requires its own certificate. Triangular metric support additionally requires
the measured cutoff range described in [Symmetries](/symmetries).

Auto never changes material sampling, Fourier support or precision. Native PT
profitability is not assumed in the browser. Requested and resolved settings,
retained methods, coordinate blocks, reused points, all attempted iterations
and fallback reasons appear in `metadata.execution`. The concise `text` field
also appears in the Workbench and on CLI stderr; `--quiet` suppresses the CLI
summary. Standard output remains machine-readable JSON. Python prints nothing
automatically; use `print(blaze.execution_summary(result_or_study))`.

| Maturity | Options and intended use |
|---|---|
| Recommended within the measured envelope | Native f64 `auto`, final accuracy acceptance, ordinary complex fallback |
| Advanced, explicitly qualified | Manual PT/Fourier choices, k-star transport, sectors, partner reconstruction, bounded geometry continuation and coarse starts |
| Explicit discretization choice | Metric Fourier support and Voronoi material averages; compare to the same pencil before claiming acceleration |
| Experimental public options | Native geometry copying, metric/secant/history/residual/response prediction; bounded anchors, rolling banks and guard expansion; no general speed recommendation |
| Experimental Rust APIs | Precision changes, shared iteration engine and specialized scheduling |

Some advanced combinations cost more than the ordinary solve. The
[replacement notes](/symmetry-changelog) retain those negative results.

## Parameter studies

```toml
[[sweeps]]
name = "radius"
target = "geometry.objects.rod.radius"
linspace = { start = 0.16, stop = 0.24, count = 5 }

[[sweeps]]
name = "polarization"
target = "polarization"
values = ["TM", "TE"]
```

Use `values` or `linspace`, with inclusive endpoints and a count. Descending
interpolation is valid. The first axis is outermost and the last varies fastest.
Each combination starts from the immutable base configuration. Results preserve
axis values, job indices, and integer multi-indices.

Thread counts, error policy, and output paths are runner options. The default
failure policy stops the study while retaining completed jobs. Native scheduling
parallelizes independent configurations with bounded result delivery.

## Native geometry continuation

<ExampleSource slug="geometry-warm-start" language="toml" />

`[bands.warm_start]` enables the native study cache independently of public
field retention. The section is omitted by default. Do not combine it with
`bands.symmetry.continuation`; they select different history implementations.
The [theory and measured limits](/geometry-warm-starts) explain the predictor
ladder, Gamma kernel, final certificates and fallback behavior.

| Option | Default | Meaning |
|---|---|---|
| `method` | `copy` | `cold`, `copy`, `metric`, `secant`, `history`, `residual`, `response` |
| `scope` | `gamma` | Gamma, explicit `anchors`, or all requested `path` points |
| `anchors` | `[]` | Additional exact reciprocal-fractional points; Gamma remains included |
| `donor_selection` | `same_k` | Same-k geometry donor, `previous_k`, or cheap `screened` selection |
| `parameter_order` | `grouped` | Compatible geometry groups; optional reflected `serpentine` order |
| `guards` / `max_guards` | `2` / omitted | Solved guard count; optional bounded boundary expansion up to 32 |
| `history` | `2` | One to eight accepted snapshot blocks per fiber |
| `innovation_columns` | `0` | Optional two-snapshot history compression; one to 64 older directions |
| `innovation_relative_tolerance` | `0.001` | Relative innovation-rank threshold, with a native precision floor |
| `max_predictor_columns` | `0` | Zero selects twice the retained positive window; explicit cap at most 512 |
| `max_preparation_bytes` | `67108864` | Predictor workspace allowance per worker |
| `max_cache_bytes` | `67108864` | Global native bank payload allowance divided across worker chains |
| `retain_tm_actions` | `false` | Retain exact same-k TM source actions on their immutable basis |
| `response_iterations` | `2` | Inner response budget, one to 64 iterations |
| `response_tolerance` | `0.25` | Relative inner response stopping request |

The requested band count and public job IDs do not change. Ordinary k-path
tracking remains in the supplied order. Each worker has a cold chain root;
checkpoint resume restores results but starts new spectral history. A small
cache may evict donors or decline insertion while the solve still completes.
Payload limits exclude solver/library scratch and requested output arrays.

`metadata.geometry_warm_start` records candidate selection, parents, guards,
rank, preparation, all correction attempts, fallback and cache payload. A
geometry donor that fails admission cannot replace the last accepted state.
PT/sector coordinates, metric support and reordered k traversal retain their
existing solver and explain why raw native history was declined. Native history
does not silently transform between incompatible coordinate systems.

## Operators, registry studies, and stencils

<ExampleSource slug="operator-point" language="toml" />

`band_lo` is zero-based. The solved window includes lower bands, retained bands,
and upper remote bands. Arrays record the actual band-index sets.

Supported quantity groups are `velocity`, `mass_tensor`, `r_derivatives`,
`born_huang`, `slow_coefficient`, `exact_tm`, and `overlap`, subject to the
polarization and reference requirements of the current formulation. Dependency
quantities may be computed automatically; computed and retained quantities are recorded.

```toml
[operators.registry]
object = "hole"
points = [[0.0, 0.0], [0.25, 0.25]]
fd_step = 0.001

[operators.k_stencil]
points_per_axis = 3
half_width = 0.02
```

Generic sweep axes are outermost, registry points follow, and a stencil runs at
each configuration. Registry translations start from the base model and wrap
periodically. Independent registry points retain independent gauges.
K-stencils solve the center first and transport along the existing adjacent walk.
Returned sample order is recorded separately. A one-point stencil is valid.
Overlap extraction needs a reference source; stencil neighbors use internal references.

## Python

<ExampleSource slug="square-rods" language="python" />

- `Config.from_file`, `.from_toml`, and `.from_dict` validate through Rust.
- `config.to_dict()` and `.to_toml()` expose normalized settings.
- `blaze.solve(config)` runs exactly one calculation and returns a dictionary.
- `blaze.run(config, threads=4)` returns results, errors, and run statistics.
- `blaze.stream(config)` yields completed records incrementally.
- `blaze.build_info()` and `.capabilities()` report the installed backend.
- `blaze.execution_summary(result_or_study)` reports requested and actual execution.

Simple band calculations also accept scalar convenience arguments to `blaze.solve`.
Numerical lists do not implicitly create sweeps. Plotting and terminal output are optional extras.

| Dataset | NumPy shape |
| --- | --- |
| `frequencies` | `(k_point, band)` |
| Operator `eigenvalues` | `(solved_band,)` |
| Operator `eigenvectors` | `(solved_band, ny, nx)` |
| `velocity_matrices` | `(direction, retained_band, solved_band)` |
| `w_matrices`, `mass_tensor_inv` | `(direction, direction, retained_band, retained_band)` |
| Registry and metric derivatives | `(direction, retained_band, solved_band)` |

Arrays use C order, with flattened grid index `iy * nx + ix`. Complex output is
NumPy `complex128`, including when solver storage uses `f32`. Metadata records
storage and accumulation precision, coordinates, convergence, provenance, and shapes.
Raw eigenvectors from different gauges should be compared through subspace invariants.

For mode visualization, `blaze.align_modes(result, reference_fields,
reference_frequencies, bands=[0, 1, 2], weights=epsilon)` returns separate
`fields`, a unitary `transform` and cluster diagnostics. Supply one reference
k point on the same physical cell/grid and in the same coordinate convention;
frequencies use Blaze's units. `bands` contains source indices, even when path
tracking has reordered them. TE defaults to Euclidean weights; TM requires
positive physical mass/quadrature weights. Both spectra must contain a separated
upper guard band beyond each selected complete cluster. The helper rejects
split clusters, incompatible spans and nonorthogonal frames. It preserves
pointwise summed cluster intensity and leaves the solve gauge and certificates
unchanged. Its returned visualization frame needs fresh certification before
numerical reuse; a nearly degenerate rotation is not automatically a set of
exact eigenpairs.
`eigenvalue_atol` and `eigenvalue_rtol` bound each cluster's squared-frequency
spread in both spectra. An independently computed reference may need an explicit
larger tolerance for numerical splitting; the helper never infers that permission
from a similar-looking image.

`blaze.OperatorDataExtractor` retains native reference-field, external dielectric,
and checkpoint workflows. Its methods take the shared configuration. External
fields use a complete solved-band block; reference overlaps select the retained window.
External dielectric input declares `dielectric.source = "external"`, an empty
object list, and one sampled band point. These inputs are unavailable in the browser.
This sampled-point entry point supports the ordinary spatial solve and final
accuracy acceptance; nondefault symmetry options are rejected explicitly.

## Command line and export

```shell
blaze2d config validate calculation.toml
blaze2d config normalize calculation.toml
blaze2d config describe
blaze2d run calculation.toml -o results.npz
```

Both the Python entry point and native CLI share the contract. Use `blaze.save`
and `blaze.load` for `JSON` or `NPZ`. `write_ndjson` and `read_ndjson` support streams.
Exports include explicit array descriptors and complex encoding. `NPZ` includes a
UTF-8 metadata manifest and loads without pickle. Checkpoint resumption validates
the normalized configuration and build before skipping completed jobs.
